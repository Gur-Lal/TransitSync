# TransitSync simulation logic

Use this when working on Epic 1 (Simulation Engine) or Epic 2 (Decision Engine) code. The source of truth is the Mathematical Foundations wiki page. If code and the page disagree, stop and point out the difference instead of picking one.

## Core formulas

- **Break-even rule.** Hold h seconds only if Benefit(h) > Cost(h)
  - Benefit(h) = N(h) * H * w_wait
  - Cost(h) = L * h * w_onboard + downstream cost
  - All in passenger-seconds
- **Passengers caught by a hold.** N(h) = M * [F(h + s) - F(s)]
  - M = group size of the arriving train (swept parameter)
  - F = walking time CDF (log-normal or gamma, parameters from `config/`)
  - s = connection window, time between the feeder arrival and the scheduled departure, in either direction (REM to Metro or Metro to REM)
  - Do not use M * F(h + s): that counts people who connect without any hold
- **Hold search.** h* = argmax over X = {0, 5, ..., h_max}. Always include h = 0
- **Delay propagation.** arrival_i = max(natural_i, arrival_(i-1) + h_min)
- **Terminal slack.** carried = max(0, delay - slack), slack = layover
- **Dwell.** REM: fixed scheduled dwell, boarding limited to min(B_waiting, C_door * d_sched * n_doors). Metro: d = d_min + beta_b * B + beta_a * A, coefficients swept
- **Prediction error.** estimate = t_actual + kappa * e, with e ~ Normal(mu(tau), sigma^2(tau)). kappa = 0 is perfect-information mode
- **Queueing.** Q(t) = A(t) - D(t). Per-passenger delay is a timestamp difference

## Structural rules

- Safety rules (maximum hold, minimum gap, one-hop) are enforced in the simulator's rule checking layer, never inside a strategy. A strategy proposes; the simulator reduces or refuses and logs why
- Strategies receive an immutable observation and return actions. They never hold references to simulator state
- The controller works in both directions, so a hold at one interchange can delay a train that feeds another interchange on the REM line. The one-hop rule stops the chain after one hold
- Every random draw comes from its own SeedSequence substream: walking times, group sizes, run times, disruptions, loads, prediction errors. Dwell is not random
- Pulsed arrivals only. A constant arrival rate makes h cancel out of the break-even rule and the project's result disappears
- Ties in the event queue resolve in a fixed, documented order

## The six strategies

No control, schedule-based holding, headway regulation, predictive connection protection, rolling-horizon optimization (US-2.6 only), adaptive mode switching. All implement the same frozen controller interface.

## When implementing

1. Name the wiki section and user story the code implements in the docstring
2. Use the same symbols as the wiki in variable names where possible (`n_caught`, `headway`, `load`, `hold`, `conn_window`)
3. Write a hand-calculated test before or with the code
4. State units in every function signature or docstring

## When reviewing

Check, in this order:
- Units consistent (seconds, passenger-seconds)
- N(h) uses the difference form
- h = 0 is a candidate
- Safety rules are not enforced inside the strategy
- No unseeded randomness and no shared generator between sources
- Delay from holds is recorded separately from delay generated by disruptions
- Off-by-one on the connection window sign (feeder late vs early)

Report each finding with the line, what is wrong, and a concrete input that shows it.
